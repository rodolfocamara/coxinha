# Dash navigation and Sana content

## User-selected direction

The user selected the navigation from option 1 (Dropbox Dash) and the content treatment from option 3 (Sana AI). This increment keeps the top brand, collapsible vertical navigation, recent notes and settings footer. The content uses a quiet page title, more readable spacing and restrained dividers. It does not add an AI chat, automatic capture, cloud processing or calendar behavior.

## Implementation and boundaries

Spec 0065 describes the contract. Sol 6.1 implemented the bounded change. `CaptureSection` is controlled presentation; `LibraryView` retains capture state and IPC ownership. The shell shares one native window controller between the brand and content drag regions. Closing still requests the existing desktop confirmation and save lifecycle.

The board canvas, note persistence and native lifecycle implementation are unchanged. The previous sidebar review findings concerning brand dragging, collapsed ARIA relationships, shortcut discoverability and dead navigation keys were addressed.

The source is pinned in `target/dash-sana-validation-20261024/implementation-source-pin.json`. The independent review snapshot is in `review-r1/`; the working tree includes earlier uncommitted work and must not be interpreted as only this increment.

## Validation

- Complete frontend suite: 40 files, 211 tests passed.
- TypeScript and production frontend build passed.
- Desktop build with `local-processing,tauri/custom-protocol` passed.
- Browser evidence is recorded separately in `browser-audit.json`, screenshots and the reproducible audit script. It uses real React components and synthetic IPC with fictional data, not the user's vault.
- Native window dragging, resize, system theme events and Windows acceptance remain separate checks. Browser capture controls do not prove physical audio capture or transcription quality.

Fable completed the independent review without blockers, reproduced 45 focused tests and executed 10 adversarial probes. The formatting finding in `NoteEditor.tsx` was corrected; a comparison confirms that this post-review delta changes whitespace only. Prettier, TypeScript and both builds passed afterward.

The final browser audit passed in both themes at widths 800, 900, 1024, 1100, 1200 and 1440 pixels. The 1024/1100 screenshots were inspected specifically for the reviewer's intermediate-width concern; text wraps and controls remain reachable without horizontal document overflow. The fixtures and initial locator errors were corrected before the passing run; they were not application fixes.

The installed binary and final file hashes are pinned in `installed-manifest.json`, including an explicit aggregate-hash algorithm. The original agent aggregate hash is not relied upon; per-file hashes validated the review snapshot. The launcher now selects `coxinha-desktop-dash-sana-v1`, with its previous content backed up as `launch-demo.before-dash-sana-20261024`. Existing vault, configuration, cache and data paths are unchanged. The running application was not stopped or restarted.

## Remaining low-priority findings

- Multiple-tab close/new actions have pre-existing localization and keyboard-accessibility debt. Current routes supply only one page, so these controls are not visible.
- Some pre-existing Portuguese locale keys fall back to English.
- Single-page chrome and the page heading both identify the current view. The duplicate tab chip was removed; this remaining hierarchy is intentional for this increment.
- The HomeCanvas baseline was incomplete. Its older anchor-to-router-Link change must not be attributed to this increment.

Native Linux/Windows interaction and user acceptance remain pending. No commit, push, deployment or external-data changes were made.

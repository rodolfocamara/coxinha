# Board (Workspace canvas)

The board is the canvas of the Workspace (`/workspace`, spec 0096 P5). A note and an activity are the same object: an activity is a board item of kind `card` (progress, area, dependencies), a note on the board is the same Markdown file as a `text` item, and a note may be off the board entirely. "Virar atividade" changes only the item kind (progress starts at 0); the file and its text never change. Cards never own note content and are never edited in place: the Workspace side editor (`features/workspace/SideEditor.tsx`, the note editor in its `workspace` variant) is the only editor. Removing cards or dependencies does not remove Markdown files or index entries.

`<vault>/.coxinha/board.json` is canonical user-authored data, not a cache. Include the complete `.coxinha` directory together with Markdown notes in backups. The JSON contains a schema version, monotonic revision, colored areas/cards and directed dependencies. Note UUID references also retain the relative Markdown path so rebuilding the SQLite index can recover the reference. Missing notes retain their cards for recovery. Dependencies exist only between `card` items (the backend rejects others), so turning an activity back into a note drops its dependencies.

Writes lock `board.lock`, compare revisions, validate geometry/references, sync a temporary file, atomically replace the canonical file and sync its directory on Unix. No board data is stored in localStorage. A conflicting writer is rejected without overwriting the saved board. Recovery exports use unique filenames, sync files and directory metadata, and never replace the canonical board. The UI retains local edits, offers a recovery JSON export inside `.coxinha/recovery/` and requires explicit discard confirmation before reloading the saved version. Other save errors retain changes and offer retry. The process-wide session registers with the desktop exit save barrier, including when the Workspace route has unmounted.

Pan/zoom, a minimap and draggable nodes use `@xyflow/react` 12.12.0 (MIT). Each card's node wrapper carries the shared view-transition name `card-<itemId>` (class `card`) so Hoje's preview, the drawer and checklist lines morph into it. Moving an area moves its cards; dropping a card in an area assigns it and the area grows to fit. Keyboard: Enter on a focused card opens it in the side editor, arrows move the selected item, Delete removes only a selected dependency; the drawer's "No quadro" list is the accessible outline.

Focused verification: `npx vitest run src/features/board src/features/workspace` and `cargo test -p coxinha board::tests --lib`.
